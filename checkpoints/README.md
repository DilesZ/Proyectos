# Checkpoints

## Purpose

This folder stores the minimum durable state required to continue the project from any session, account, or PC.

## Files

- `current.md`: the latest active state
- `edit_log.md`: mandatory log of every file edit
- `session_template.md`: template for new handoff notes
- optional dated notes: `YYYY-MM-DD.md`

## Rules

- `current.md` must always reflect the latest truth.
- `edit_log.md` must be updated every time any file is edited.
- If a session changes strategy or state, update `current.md`.
- If the session is important, also create a dated note.
- Keep checkpoints short, factual, and actionable.

## Recovery Protocol

Start any new work session by reading:

1. `system.md`
2. `memory.md`
3. `agets.md`
4. `skills.md`
5. `checkpoints/current.md`
6. `checkpoints/edit_log.md`

## Checkpoint Standard

Each checkpoint should include:

- date
- active track
- active mission
- current state
- completed actions
- proof
- blockers
- next action
