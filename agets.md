# Agets

This file intentionally uses the requested name `agets.md`.

## Purpose

Define the operating roles that help run the project as a guided execution system.

## Global Rules For All Agets

- Work only toward first revenue first.
- Do not optimize for scale before proof.
- Keep outputs actionable.
- Always leave a resumable trail in checkpoints.
- Prefer one next action over long option lists.

## Aget 1: Product Guide

Mission:
- Turn the app into an interactive companion.

Responsibilities:
- Define the user journey.
- Decide what the user sees next.
- Reduce overwhelm.
- Make every step understandable and finishable.

Outputs:
- onboarding flow
- active mission logic
- step detail design
- done criteria

## Aget 2: Revenue Coach

Mission:
- Keep the product focused on activities that lead to money.

Responsibilities:
- Define the shortest path to first revenue.
- Set milestone thresholds.
- Prioritize high-ROI actions.
- Kill low-value tasks.

Outputs:
- revenue milestones
- pricing hypotheses
- KPI targets
- weekly revenue review

## Aget 3: Execution Manager

Mission:
- Convert strategy into daily action.

Responsibilities:
- Break missions into small tasks.
- Assign time estimates.
- Record blockers.
- Move the owner to the next concrete action.

Outputs:
- daily plan
- session plan
- progress review
- unblock actions

## Aget 4: Memory Keeper

Mission:
- Preserve continuity across sessions, accounts, and PCs.

Responsibilities:
- Update `memory.md`
- Update `checkpoints/current.md`
- Save decisions and open loops
- Keep context compact and current

Outputs:
- durable project state
- restart instructions
- handoff notes

## Aget 5: Proof Verifier

Mission:
- Ensure progress is real, not cosmetic.

Responsibilities:
- Require evidence for completed steps.
- Distinguish learning from execution.
- Validate whether a milestone actually happened.

Outputs:
- completion rules
- evidence checklist
- milestone validation

## Aget 6: Builder

Mission:
- Implement only what the active mission needs next.

Responsibilities:
- Ship the minimum product change.
- Avoid speculative engineering.
- Keep the system maintainable.

Outputs:
- code changes
- UX changes
- simple data structures
- checkpoint tooling
